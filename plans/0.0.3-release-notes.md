# Herdchestra 0.0.3 发布说明

- **版本**：`0.0.3`（唯一版本源 `src/hc/version.cljc`）
- **日期**：2026-11-09
- **状态**：工作树实现清单，**不是已放行发布**。最终冻结 bundle、源码树哈希与门禁结果见
  `plans/0.0.3-gate-checklist.md` 与 `plans/e2e-master-status-0.0.3.md`。
- **口径**：本文件只从工作树文件与 `git diff` 归纳；「测试」列是已存在的覆盖入口，不代表
  已在 0.0.3 冻结树上运行。状态标记：`DONE` = 工作树有实现/测试入口；`PARTIAL` = 只有一部分
  落地；`NOT DONE` = 缺口仍开放。

## 目标摘要

0.0.3 的目标是在 0.0.2 的 22/22 手工/真实端点基线上，补齐 **Steward/Sphinx 运行时**、
**统一提示词与 EDN+UFSS 铁律**、**规模性能/可重建检索/存储治理**、**客户端控制权/取消语义/
视觉收口**、**七边界确定性验证**，并以 **22/22 E2E + 版本身份 + 发布门禁** 收口。发布只认
最终冻结 bundle 与源码树双哈希；本文件不预写 PASS。

## 缺陷收口（0.0.3 收尾期）

### ① 已修复：启动期同步全量 FTS 重建导致 1000 会话启动挂起

- **现象**：1000 会话的 app 启动迟迟不返回，超过 bench 的 300s 等待后被
  SIGKILL。
- **根因**：`hc.server.app.system/ensure-history-index!` 在 `http/start!`
  **之前**同步执行全量 FTS 重建。实测 **100 会话 62,256 ms**（622 ms/会话、
  6,200 postings），按线性投影 **1000 会话约 620s**，远超 300s。
- **修复**：`system.clj` 把必需重建延迟到 daemon 线程
  `hc-history-index-bootstrap`，启动返回
  `{:deferred? true :state :building}`；`history-index-health` 在构建期报
  `:state :building`；`history/index.clj` 的 `rebuild!` 不再整轮持 store 锁，
  改为逐会话短锁，并用 `:stale-snapshot` 防止后台重建覆盖并发增量写入。
- **验证**：`bench-1000` **PASS ×3**（listen **17.25s / 16.65s / 16.34s**，
  均 < 60s，exit 0）；`system-test` **31/203**、`system-lifecycle-test`
  **4/55**、`--check` exit 0、`startup-scale-test` **1/39** 全绿
  （`open 1.14 ms`、`summary-read 16.0 ms`、`registry-list 15.1 ms`）。
  以上为当前树结果；三项基准已在最终 `751756ec` / `80e9321c` 上 PASS
  （见下节）。
- **语义影响**：`:state :building` **不**让 `:ok` 变 false
  （`component-errors` 为空；`health.clj` 仅看 `empty? component-errors`）。
  启动返回的是「已接受、后台建索引」，不是「索引已完整」。

### ② 已澄清（非缺陷）：1000 会话列表首屏只显示 200 条

- **现象**：1000 会话时列表首屏只显示 200 条，表头显示 `200 / 1000`。
- **根因/机制**：`:ui/session-limit` 默认 **200**（`db.cljs:59`）；

  `200 / 1000`，并有「显示更多会话（还有 N 条）」每次 **+200**

  发布全部会话摘要。
- **修复**：无（不是截断，不需要改代码）；保留分页机制。用户可点四次到
  1000，或用搜索直接定位。
- **验证/数字**：`bench-1000` 按首屏计数 **200** 属预期；若要测 1000 行
  渲染，必须先点「显示更多」。**§8.5 无功能缺陷**。

- 根 `AGENTS.md` §7.1 的数据政策：**1.0.0 前不承诺当前态数据的跨版本兼容；升级可丢弃旧状态，不视为故障。** 因此 `0.0.0 → 0.0.3` 不提供迁移保证；需要保留资料时先做加密备份。
- `"search"` 是**派生分区**，不进入备份与整库恢复（`storage/export.clj` 的
  `derived-partitions`）。恢复后必须由可信调用方执行 `:history/reindex` 重建；
  当前工作树已有启动时 `ensure-history-index!`，并已构造、传入 handler maps
  （`system.clj:4814-4831`、`:5311-5314`）。原 D-32 已从 `DEBT.md` 删除；
  冻结前仍应在冻结 bundle 上用真实命令复核。查询在索引缺失时返回
  `:missing`，不会把空索引伪装成完整结果。
- `session-index` / `session-summary` / `session-ref-index` 是会话派生文档。旧库缺失时，首次读取最多做一次全分区扫描并回退到权威记录；下一次提交写回派生文档。这不是启动时批量迁移，也不改变权威会话记录。
- 版本号变更影响 `version.cljc`/`pixi.toml`/`package.json`/`package-lock.json`
  （根 `version` 与 `packages[""].version` 两处）/`--version`/health；
  任一处不一致时 `scripts/release-gate.sh` 直接失败。

## 已知限制

- 浏览器录音（MediaRecorder 产出 WebM）不支持云端 STT：`POST
  /speech/recordings` 返回 400 `SPEECH_DURATION_UNVERIFIABLE`，录音保留但
  provider 未被调用；本地（device）STT 可用。详见 `DEBT.md` D-45。
- E2E 必须使用宿盘 `TMPDIR`：`/tmp` 是 32G tmpfs，写满会产生假「连接
  中断」/「录音时长无法校验」等失败；统一
  `TMPDIR=/var/tmp/hc-e2e`。
