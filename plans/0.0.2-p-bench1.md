## 命令

```sh
# 1) seed（一次，产物 /tmp/hc-bench1/run/data/db，81 MB）
node scripts/bench-1000-dom.mjs --root /tmp/hc-bench1/run \
  --sessions 1000 --messages 20 --msg-chars 400

# 2) 有效跑法（跳过 seed 复用已生成 DB）
HC_JVM_OPTS='-J-Xmx4g,-J-XX:MaxDirectMemorySize=512m,-J-XX:MaxMetaspaceSize=512m,-J-Xss512k,-J-XX:+ExitOnOutOfMemoryError' \
HC_LISTEN_TIMEOUT_MS=1500000 \
HC_CHROME_HEAP_MB=3072 \
node scripts/bench-1000-dom.mjs --root /tmp/hc-bench1/run \
  --sessions 1000 --messages 20 --msg-chars 400 --skip-seed \
  --json plans/evidence/p-bench1/result.json
```

脚本改动（仅 `scripts/bench-1000-dom.mjs`，未碰 `src/`）：
- `JVM_OPTS` 增加 `HC_JVM_OPTS` 覆盖（默认值不变）；
- `waitForListening` 超时可由 `HC_LISTEN_TIMEOUT_MS` 配置（默认 300s 不变）；
- Chrome `--js-flags` 堆大小可由 `HC_CHROME_HEAP_MB` 配置（默认 512 不变）。

## 按需渲染证据

- 1000 个会话的 state 进入客户端后，DOM 中仅渲染 200 个 `.wb-session-item` 行（前端 `ui/session-limit` 默认 200 上限，`main.js` 中 `re.l(200, ...)` 钳制）；
- 全页 DOM 节点仅 2 591，打开后选中会话再选中其 20 条消息，总 DOM 仅增至 2 592，消息区 337 个节点——**按需/窗口化渲染生效**；
- 同步徽章在 7.8 s 后达成「已同步」，未出现卡死。

## 热点分析（src 未改）

1. **启动建 Owner 是主要瓶颈**：`system.clj` 在 listen 前对 1000 个会话逐个调用 `session-owner-factory`（每个 Owner 装配 workspace-runtime / program-runtime / browser-service 等十余个对象），listen 耗时 387 s。384m 堆下 healthz 期间 `registry/list-sessions` → `load-sessions` → 逐会话 `ports/read-session`（全量含 messages）→ `sessions/list-sessions` 投影，1000 会话读放大后 OOM。
2. **healthz 503 根因**：`health.clj` 的 `snapshot` 要求 `session-count` 非 nil；`list-sessions` 在 2g 堆下 120s 探测窗口内未返回（返回慢或超时），故 `ok?` 为 false → 503。即使服务可用，健康检查在 1000 会话规模下不可用。
3. **峰值 2.75 GiB > 2 GiB 门槛**：`app/snapshot.clj baseline` 的 `histories` 把**每个会话全部消息实体**（含 `:content` 正文）放入 `:session/history` / `:message/by-id`，20 000 条 × ~400+ 字符正文经 EDN 序列化进 state 快照，是 JVM 堆的主要占用；Chrome 侧默认 512m JS 堆曾页面崩溃（run2 run3 前），3g 堆才稳定——前端全量持有快照是第二热点。
4. **按需渲染已正确**：DOM 侧无问题，问题在服务端快照构建与启动串行建 Owner。

## 结论

**FAIL**（相对门槛）：

- 启动耗时 387 s ≫ 任何可接受的 SLO；384m 生产默认堆下服务在 healthz 阶段 OOM 崩溃——**必须修**。
- 峰值 2.75 GiB > 2 GiB 上限——**超标**。
- healthz 持续 503，健康检查在该规模下失效。
- 列表打开 8.3 s ≥ 5 s 门槛——**超标**（含 7.8 s 快照同步等待；纯渲染很快）。

**通过项**：DOM 按需渲染（200 行上限、2.6k 节点）、会话内消息渲染（69 ms 选择、337 节点）均健康。
