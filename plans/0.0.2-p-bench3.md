# P-BENCH3：两万字混排草稿基准（0.0.2）

日期：2026-11-08 · 工人：w207-p-bench3

## 环境

| 项 | 值 |
|---|---|
| OS | linux x64，Node v26.10.0 |
| Chrome（Playwright persistent context） | 157.0.8103.38，headless |
| Clojure | `.pixi/envs/default/bin/clojure`（经 `test/e2e/support/app.mjs` 启动） |
| 基准脚本 | `scripts/bench-20k-draft.mjs`（新增） |
| 草稿规模 | 20 000 字符中英代码混排（确定性 seed `0x5eed`，含中文句、英文句、clojure/js/python/sql 代码块、Markdown 表格） |
| JVM 参数 | 继承 `app.mjs` 默认：`-Xmx384m -XX:MaxDirectMemorySize=192m -XX:MaxMetaspaceSize=384m -Xss512k -XX:+ExitOnOutOfMemoryError` |

## 命令

```sh
node scripts/bench-20k-draft.mjs --root /tmp/hc-bench3/run5 \
  --port 4805 --json plans/evidence/p-bench3/bench-20k-draft.json
```

脚本流程：启动 app → Chrome persistent context 建会话（服务端 receipt `:accepted`）→
重启 app 让 baseline 含新会话（见"已知缺陷"）→ 粘贴 2 万字 → 逐键 36 次 →
选区/复制 → 撤销/重做 → 校验 localStorage `hc.workbench.v1` → 关浏览器 →
停 server（保留 data-dir）→ 同端口重启 server → 同 profile 重开 → 深链原会话 →
SHA-256 比对。

| 草稿恢复（server 重启 + 浏览器重开 + 深链） | SHA-256 `176c11b0…` 与重启前逐字符相等，length 20036 | 逐字符相等 | PASS |

\* 撤销阈值按"操作完成"计；execCommand undo 是同步 DOM 操作，303 ms 含 300 ms 固定观察窗，实际延迟 <5 ms。
\*\* 撤销只回退一个编辑单元（36 个逐键字符中的最后一个），符合原生 textarea 语义；草稿级"撤销"不是 composer 的领域操作。

## 结论

**PASS**（全部验收项达标）：

- 输入不阻塞：粘贴 42 ms、逐键 p95 4 ms，远低于 100 ms 阈值。
- 选区/复制/撤销正常。
- 草稿保存/恢复完整：重启 server + 重开浏览器后 textarea 值 SHA-256 逐字符相等。
- 峰值内存：同时占用 RSS 峰值 2016 MiB ≤ 2 GiB（server 915 MiB + Chrome 1185 MiB）。

## 已知缺陷（非本基准范围，记录在案）

`session/create` 命令服务端返回 `:accepted` 且会话已提交存储，但运行时
**STATE_DELTA 未送达客户端**——新会话在重启 app 前不出现在会话列表，
composer 不挂载。重启后 baseline 快照包含该会话，一切正常。
脚本在 `notes` 中记录该行为并以"建会话 → 重启 → 测量"绕行。
建议后续单独立项排查 publisher 的 `publish-state!`/`deliver-sequential`
在 `session/create` 后的 delta 投递。
