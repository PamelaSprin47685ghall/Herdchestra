# Herdchestra 0.0.1 E2E 01–22 执行手册

> 权威顺序：根 `AGENTS.md` §8.5（剧本与放行门槛）> §7.3（AG-UI/Sente）> §7.4（八段用户旅程）> §8.4（三层验证）> `RUNNING.md`（0.0.1 启动）> `HACK.md` §1（本机环境）。
>
> 本文件是**执行手册**，不是验收报告。写作时只做了只读调研与环境探测；22 条 E2E 均未在本手册中执行。执行后必须逐条写 `PASS` / `FAIL` / `BLOCKED` / `NOT RUN`，不得把未执行写成通过。
>
> 证据标签沿用 `HACK.md`：`[MEASURED]` 本机实测；`[SPEC]` 规格写明；`[INFERENCE]` 由代码/依赖推断；`[NOT RUN]` 未执行。

## 0 使用方式与判定规则

1. **一条 E2E 的完成** = 该条“必须通过的检查项”逐项有证据，且证据能回答四个问题：用户看到什么、用户做了什么动作、结果属于哪个对象、退出/重开后什么仍在。
2. **视觉相似不算完成**。截图只能证明渲染，不能证明状态归属、持久化、费用口径或外部副作用。
3. **四种结局分开写**：尚未写入的拒绝、已完成的应用、仍在运行/等待的动作、硬失败后的不确定现场。禁止压成一个布尔 `success`。
4. **BLOCKED 不是 PASS**。缺模型、缺浏览器、缺硬件、缺权限时写 `BLOCKED`，并给出替代取证；替代取证只能证明相邻契约，不能冒充该条通过。
5. **证据脱敏**：任何日志、截图、导出、备份都不得包含真实 API key、Authorization 头、cookie、备份密码、私钥、用户私人数据。合成样本按 §8.5 要求使用短消息、多语混排、约两万字草稿、三行表格、扫描材料、含自我纠正的录音。
6. **运行时口径**：发布验收用 Pixi（JDK 21 / Clojure 1.12.6 / Node 22）。宿主 JDK 26/27 只用于快速定位，不能作为 0.0.1 运行时证据。

### 0.1 证据目录约定

| 层 | 路径 | 内容 | 是否入库 |
|---|---|---|---|
| 原始证据 | `/tmp/hc-e2e/<run-id>/E2E-NN/` | 完整日志、截图、EDN 响应、导出文件、临时数据库副本 | 否 |
| 持久结论 | `plans/e2e-evidence/E2E-NN/verdict.md` | 环境、命令、逐项断言、结论、证据摘要 | 可入库（脱敏后） |
| 发布汇总 | `plans/e2e-evidence/0.0.1-summary.md` | 22 条总表、PASS/FAIL/BLOCKED/NOT RUN、阻断项 | 是 |

每条 E2E 至少保存：

```text
run.md                执行人、日期、提交、运行时、命令、数据目录、端口
healthz.edn           启动后与重启后的 /healthz 原文
server.log            服务端 stdout/stderr（脱敏）
commands.log          实际执行的命令与退出码
screenshots/          关键状态截图（文件名带步骤号）
exports/              导出文本/Markdown、备份清单、恢复预览
verdict.md            逐项断言与结论
```

`run-id` 建议用 `YYYYMMDD-HHMM-<short-sha>`；不要复用旧目录，避免旧证据污染新结论。

## 1 运行前基线（所有 E2E 的共同前置）

### 1.1 环境与构建

```bash
# 本机 Pixi 不在 PATH；HACK.md §1 记录为 /tmp/pixi
/tmp/pixi --version                 # 期望 0.83.x
/tmp/pixi install --locked
/tmp/pixi run client-install        # npm ci
/tmp/pixi run client-release        # 生成 resources/public/js/main.js 与 CSS

# 隔离自检：不写默认数据目录，避免与其他进程/旧状态冲突
/tmp/pixi run clojure -M:server -m hc.server.app --check --port 0 \
  --data-dir /tmp/hc-e2e/app-check-data \
  --workspace-root /tmp/hc-e2e/app-check-work \
  --static-root resources/public
```

`pixi run app-check` 也接受，但它使用默认数据目录；发布证据优先用上面的显式路径。健康 EDN 必须包含：

- `:ok true`
- `:version "0.0.1"`
- `:store {:open? true}`
- `:gateway` 计数
- `:models {:configured? false}`（无模型时仍健康，聊天必须明确提示先选模型）

真实启动与静态资源：

```bash
/tmp/pixi run app
curl -s http://127.0.0.1:7575/healthz
curl -sI http://127.0.0.1:7575/          # 200，返回客户端 shell
```

### 1.2 测试入口

| 层 | 命令 | 说明 |
|---|---|---|
| 全量 Clojure | `/tmp/pixi run test` | `clojure -X:test:compose:server:client`；记录测试数、断言数、失败数、seed、退出码 |
| 定向 Clojure | `clojure -M:test:server -n <ns>` | 单个/多个命名空间；宿主或 Pixi 均可 |

### 1.3 每次运行必须新建的隔离目录

```bash
RUN=/tmp/hc-e2e/$(date +%Y%m%d-%H%M)-$(git rev-parse --short HEAD)
DATA=$RUN/E2E-NN/data
WORK=$RUN/E2E-NN/workspace
STATIC=resources/public
```

- 每个并行进程必须有独立 `--data-dir`；Datalevin 同一目录只允许一个写进程。
- 端口用 `--port 0` 让系统分配；若必须固定端口，先探测空闲。
- 浏览器 profile 必须独立（`--user-data-dir`），不要复用日常 Chrome profile。

### 1.5 可直接用于取证的 HTTP/CLI 入口

这些入口只用于准备/取证，不替代 Sente 业务命令。所有请求走 loopback + 同源策略；默认不要放开远程。

| 入口 | 方法 | 用途 | 证据 |
|---|---|---|---|
| `/healthz` | GET | 健康、版本、store、gateway、models | `healthz.edn` |
| `/api/workspace/list?path=<rel>` | GET | 文件列表、`(mtime,size)` stamp | `workspace-list.edn` |
| `/api/workspace/read?path=<rel>` | GET | 文件文本 + 完整 stamp | `workspace-read.edn` |
| `/api/workspace/stat?path=<rel>` | GET | 存在性/类型/stamp | `workspace-stat.edn` |
| `/api/workspace/search?q=<text>&limit=<n>` | GET | 文件名搜索（有界） | `workspace-search.edn` |
| `/attachments?name=<name>&draft-count=<n>` | POST | 原始字节上传，返回 descriptor | `attachment.edn` |
| `/attachments/extract` | POST | 显式 EDN 提取请求（页/OCR/文本路由） | `extract.edn` |
| `/speech` 或 `/speech/snapshot` | GET | 语音配置/录音/音频快照 | `speech.edn` |
| `/speech/recordings` | GET/POST | 录音列表/转写 | `recordings.edn` |
| `/speech/tts` | POST | 合成，返回音频字节 + `x-hc-audio-id` | `tts.wav` + `audio-meta.edn` |
| `/speech/translate` | POST | 翻译 | `translation.edn` |
| `/blobs/:id` | GET | 大对象下载 | `blob.bin` + 哈希 |
| `/sync-objects/:token` | GET | 大状态对象 | `sync-object.edn` |
| `/chsk` | GET/POST | Sente 握手/长轮询；业务命令走这里 | `sente.log` |

业务命令（会话、历史、设置、备份、定时、扩展）没有 REST 路由；用真实浏览器里的 bridge 或测试内的 `gateway-ports/submit-command!`。

### 2.4 资产结论

- **有零件级自动化基础**：22/22。每条至少有一个直接测试或脚本；但“有零件”不等于“剧本已闭环”。E2E 22 的零件是备份合并、扩展默认停用、已删除区保留，不是迁移驱动。
- **真实应用 + 真实浏览器已闭环**：3/22——03（选区/流式）、14（受管浏览器）、17（备份 Sente 往返）。这是目前唯一三条能同时证明“真实 UI + 真实传输/进程”的剧本。
- **严格零自动化**：0 条。不要把“没有端到端驱动”说成“完全没有测试”，也不要把零件测试说成端到端通过。
- **真实应用 + 真实模型/HTTP stub 已闭环**：01/02 的设置与模型探测、04/05 的历史、06 的附件、08 的取消、10 的重启、21 的费用有服务端或进程级证据，但多数缺完整 UI 驱动。
- **按端到端剧本标准实质缺失**：
  - **E2E 18 的“磁盘满”分支**：现有测试只覆盖“草稿保存失败保留文本”“损坏库阻断启动”“恢复失败不冒充成功”，没有 ENOSPC/空间耗尽注入，也没有“释放空间后恢复关联”的自动化。
  - **E2E 22 的跨设备迁移**：备份合并/工作区重定位/扩展默认停用是零件级测试，没有一条“旧设备资料 → 新设备导入 → 能力降级 → 关闭状态保持 → 已删除区保留”的迁移驱动。
- **关键断言未被现有自动化覆盖**：
  - 13：两个小应用与普通浏览页之间的真实 IndexedDB 隔离（`herdchestra-miniapps` 库，`kv` 以 `[app-id key]` 为键）、清除其一不影响另一。

  - 07：真实联网搜索的“同一文章两个链接”“无发布日期”站点；现有测试用本地 stub。

### E2E 01 空安装到首条可保存回复

**前置**

- 全新 `--data-dir`、空 `--workspace-root`；启动配置不含 `:models`；无历史。
- `client-release` 已完成；`/healthz` 为 `:ok true`、`:models {:configured? false}`。
- 模型：无模型分支 + stub 分支各一次。

**动作**

1. 打开 `/`，在首页输入短消息草稿（不要发送）。
2. 进入设置 → 添加模型连接（stub 或真实），填写名称/主机/密钥，点“测试连接”，启用。
3. 返回原会话，确认草稿仍在；发送；等待回复。
4. 复制回复；退出进程；用同一 `--data-dir` 重启；重开页面。
5. 另起一次：测试连接失败，返回草稿修改，不重置应用。

1. 引导不要求注册本产品云账号。
2. 从设置返回后草稿完整（文本、光标、附件/引用若有）。
3. 服务身份可见（连接名、实际主机、模型名），不把自定义主机标成官方。
4. 发送只产生一条用户消息；生成前有可理解状态（连接中/生成中）。
5. 回复可复制；重开后消息、回答、模型归属均在。
6. 测试连接失败也能回原草稿修改；失败不要求重置应用。

### E2E 02 同名模型与双服务连接

**前置**

- 两个连接（“个人模型服务”“工作网关”），各自启用同名模型（如 `same-model`），连接名可辨认。

### E2E 03 流式阅读与下一条草稿
