- 日期：2026-11-07

- 约束：单仓库、10 worker（8–12 弹性）、只写本设计文档；不改 `src/`、`test/`、`package.json`。
- 上游：`plans/0.0.2-s2-e2e.md`（17 条自动化 + 5 条手工，56–80 人日）、`plans/0.0.2-s2-features-a.md`（D-01 L / D-03 M）、`plans/0.0.2-s2-features-b.md`（D-11/12/13/19/20）、`plans/0.0.2-s2-visual.md`（高 26 / 中 24 / 低 13）、`plans/0.0.2-s2-perf.md`（≤2 GiB / ≤512 MiB / 三项基准）、`plans/0.0.2-s2-parallel.md`（冲突矩阵、构建锁、串行合入顺序）。

## 0 术语与记号

- **slice**：一个 worker 一个 turn 可交付的最小工作单元；粒度 = 一个命名空间/一个文件集 + 一个定向测试命令。
- **状态**：`READY`（输入已就绪可立即开工）/ `WAIT(dep)`（等待 slice 级依赖合入）/ `HOLD`（等待外部门禁，如冻结窗口）。
- **所有权**：worker 对文件的独占编辑权；共享热点按 `s2-parallel.md` §3.2 函数/区段级切分。
- **构建锁**：`flock /tmp/hc-build.lock` 包住一切 `npm run release`/`shadow-cljs release`；bundle sha256 记入 `plans/0.0.2-s2-builds.md`。
- **app 锁**：手工/E2E 复现浏览器验证时 `flock /tmp/hc-app-single.lock` ≤5 分钟。
- **定向测试**：worker 只跑自己命名空间的 `clojure -M:test -e "(require 'hc.x.y-test)"` 或等价过滤；**全量只由 INT 在集成点跑**。

## 2 Knuth 风格伪代码

### 2.1 数据结构

```clojure
;; slice 登记表（本文档 §1 的机器可读投影）
{:slices {<slice-id> {:owner <worker>
                     :deps [<slice-id>...]        ; slice 级依赖
                     :files [<path-or-glob>...]   ; 独占所有权
                     :hotspots {:handlers.clj :segment <name>} ; 共享热点段
                     :est-days <n>
                     :state :ready|:waiting|:merged|:blocked
                     :accept [<assertion-key>...]}}
 :locks  {:build "/tmp/hc-build.lock" :app "/tmp/hc-app-single.lock"}
 :caps   {:jvm "JAVA_TOOL_OPTIONS=-Xmx1g -XX:MaxDirectMemorySize=512m"
          :playwright-workers 1 :chrome-old-space 512}
 :milestones [:m1-feature-base :m2-e2e-harness :m3-visual-perf :m4-gate :v0.0.2-tag]}
```

不变量：
- I1：任一时刻同一文件（或同一热点段）只有一个 `state≠:merged` 的 owner。
- I2：`state=:merged` 的 slice 其定向测试在合入点全绿。
- I3：bundle 重建必在 `flock /tmp/hc-build.lock` 内；每次重建记 sha256。
- I4：全量测试只在 INT-GATE 运行；worker 只跑定向。
- I5：E2E spec 的证据 JSON 同时含 `clientBundle.sha256` 与 `sourceTreeSha256`。

### 2.2 调度循环

```text
PROCEDURE worker-loop(worker, slice-table)
  loop:
    s ← CLAIM(worker)                    // 领取 state=:ready 且 deps 全 :merged 的 slice
    if s = ⊥ then WAIT_OR_HELP()         // 无可领 slice：协助 INT 或领 :waiting 中最先解锁者
    (branch, tests) ← EXECUTE(s)         // 在独立 worktree/分支实现；只改 s.files
    VERIFY(s, tests)                     // 定向测试 + 该 slice 验收断言
    if VERIFY fails then FIX-AND-REVERIFY(s) else SUBMIT(s, branch)
    state[s] ← :submitted
    // 不自己 merge；INT-MERGE 按 §2.3 顺序收
end

PROCEDURE INT-MERGE()
  for s in MERGE-ORDER ∩ submitted do      // §2.3 固定顺序
    if HOTSPOT-CONFLICT(s, merged-set) then
      REBASE(s, merged-set)               // 后到者在先到者函数上扩展，禁重写同函数
    MERGE(s)
    state[s] ← :merged
    REBUILD-BUNDLE()                       // flock 内；记 sha256 → builds.md
    RUN-DIRECTED-TESTS(dependent-slices(s))
  end
end

PROCEDURE EXECUTE(s)
  read s2-design-doc(s)                    // 对应 plans/0.0.2-s2-*.md 节
  if s.touches-shared-file then
    assert REGISTERED(s.hotspots)          // 未登记先登记再动手（s2-parallel §6）
  implement-minimal-skeleton               // S2 钉死的语义不动
  write-tests-first-or-with                // 验收断言即测试
  return (diff, test-commands)
end
```
