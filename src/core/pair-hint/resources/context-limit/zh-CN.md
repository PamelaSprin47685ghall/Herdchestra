# context-limit

上下文窗口是 provider 声明的一个数字，它是一条事实，不是一条命令。它的用途是让判断有依据，而不是让你提前惊慌。

- 窗口大小只说明「一次请求最多能带多少 token」。它不告诉你何时会溢出，也不说明该压缩什么；不要据此预测溢出，也不要自行代为压缩。
- 压缩会丢因果。比「快满了」更重要的是「哪些事实必须留下」：当前目标、已确定的接口、未完成的义务、尚未领取的结果。把这几样写清楚，比省下几千 token 更有价值。
- 长程委托里，上下文由别人替你保留，你只负责给出可恢复的事实：结论、路径、锚点。能靠重新读取恢复的内容，不必常驻。
- 当真正接近上限时，正确的动作是把结论落成文字、把工作交出去或挂起，而不是把历史删短了继续硬撑。
- 看到「窗口很大」不等于可以挥霍；看到「窗口很小」也不等于必须立刻收尾。数字是参考，事实是依据。
