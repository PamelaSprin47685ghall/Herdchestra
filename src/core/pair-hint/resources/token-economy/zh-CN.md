# token-economy

一次请求发出去，成本由三块决定：未被缓存的输入 token、命中缓存的输入 token、输出 token。前两块价格差一个数量级，所以「省 token」的第一要务不是写短，而是别让已经缓存的前缀失效。

- 前缀缓存按请求的字节前缀命中。**稳定事实放在前面**：系统提示、工具定义、会话绑定的事实；**会变的东西放在后面**：本轮的问题、新的观察。同一段文字在两次请求里换了位置，命中就没了。
- 不要为了一点风格上的整齐去重排已有内容。一次无关紧要的编辑，可能让整段上下文重算。
- 同一份文件在一次程序里只读一次、只写一次。重复的 `cat` 是重复的输入 token，重复的 `write` 是重复的冲突面。
- 大段原文只在必要时进入对话。结论、锚点、行号通常够用；把整份文件贴进上下文之前，先问它是否真的会被用到。
- 输出按需给：交付写全，过程不铺陈。删掉的是冗词，不是证据。
- 缓存失效的诊断顺序：系统提示变了没有、工具清单变了没有、前面的消息被改写没有、注入的提示位置漂移没有。按这个顺序查，通常第一个就中。
